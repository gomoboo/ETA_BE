# 위치 공유 버그 수정 및 로컬 검증 (2026-10-08)

대상: `gomoboo/ETA_BE`, 기준 main `e17e909`, 작업 브랜치 `codex/fix-location-privacy`.

## 이슈와 변경

- [#42](https://github.com/gomoboo/ETA_BE/issues/42): 매 위치 메시지에서 현재 DB의 동의 상태를 검사한다. 미동의는 `LOCATION_CONSENT_REQUIRED`로 거부하고 위치를 저장하지 않는다. 온보딩에서 동의를 철회하면 참여 중인 모든 약속의 해당 참가자 위치를 삭제한다. 삭제가 실패해도 지도 브로드캐스트는 미동의자의 위치를 제외한다.
- [#43](https://github.com/gomoboo/ETA_BE/issues/43): 이미 체크인한 참가자의 위치 전송은 `LOCATION_SHARING_ENDED`로 거부한다. 첫 체크인 좌표, 캐시 갱신 시각, 도착 시각, 확정 지각비를 보존한다. 소켓 연결을 유지하므로 다른 참가자의 지도는 계속 수신한다.
- [#44](https://github.com/gomoboo/ETA_BE/issues/44): 나가기에서 해당 참가자의 위치 필드를 삭제한다. 마지막 참가자가 나가 취소되면 전체 위치 해시를 삭제한다. 전원 체크인은 마지막 `checkin:completed`와 `map:sync` 이후 전체 캐시를 삭제한다. 정산 완료 및 기존 영장 조회 경로에서도 전체 캐시를 삭제한다.

## 프론트 연동 변경

신규 온보딩 요청에서 `locationTermsAgreed`를 생략하면 **false**다. 실제 동의한 사용자만 명시적으로 **true**를 보내야 한다. 기존 사용자의 온보딩 갱신에서 필드를 생략하면 기존 동의 상태를 유지한다. 기존 DB의 동의 값을 일괄 변경하지 않는다. ORM/Pydantic 기본값만 변경하므로 DB 스키마 마이그레이션은 필요하지 않다.

미동의여도 REST 기능과 지도 수신을 사용할 수 있다. 위 두 WebSocket 에러를 받으면 위치 전송을 중단한다. 자세한 흐름은 [프론트 연동 가이드](FRONTEND_INTEGRATION.md)에 반영했다.

## Redis 장애 시 처리

캐시 정리 실패는 로그를 남기고 이미 확정한 DB의 나가기·정산·동의 철회를 유지한다. 미동의자는 지도 구성에서 제외하고 추가 위치 전송도 거부한다. 기존 캐시는 최대 24시간 TTL로 만료되며, 완료된 약속은 정산 재조회에서도 전체 삭제를 재시도한다. Redis 장애가 지속되는 동안 물리적인 즉시 삭제까지 보장하지는 않는다. 별도 재시도 작업 큐는 이번 수정에 포함하지 않았다.
